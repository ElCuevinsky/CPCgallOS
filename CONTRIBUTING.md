# Contribuir

1. Abre un issue describiendo el cambio y el hardware afectado.
2. Crea una rama desde `main`.
3. Ejecuta `make validate` antes de enviar el pull request.
4. No agregues IDEs, extensiones, dominios o paquetes sin justificar su uso en
   programación competitiva.
5. Nunca publiques contraseñas, hashes administrativos reutilizados ni datos de
   participantes.

Los cambios de drivers, kernel, arranque, persistencia o seguridad requieren una
prueba de BIOS, UEFI y modo competencia documentada en el pull request.
